# Full code audit — 2026-08-03

Top-to-bottom correctness + performance audit of the whole plugin on branch
`house-supplies-and-storage-rebuilds` (baseline `2079b2e`, build green).

**Method.** Multi-agent sweep: 16 auditors (12 subsystem reviewers covering every
package, plus cross-cutting sweeps for thread-safety, persistence symmetry,
resource hygiene and hot-path performance), 98 raw findings → 86 after dedup →
every finding adversarially verified (one skeptic each, instructed to refute
against the code, CLAUDE.md's contracts and DOMAIN-NOTES). 67 verified by agents
(65 confirmed, 2 refuted); 19 whose verifiers died to a session cap were
re-verified by hand — 15 confirmed, 4 refuted/downgraded in that set.
**Result: 10 fix commits (`80b7e37..c08739e`), 68 findings fixed with pinning
tests, 12 confirmed findings reported below unfixed** (live-client verification,
detection semantics, or a Luke ruling needed). Full build green at every commit.

## Fixed — highs (worst first)

1. **StackOverflowError + lost flush at logout** — `AccountState.foldRateSample`
   called `persist()`; from the logout/hop flush (gameState already off
   LOGGED_IN) that re-entered `persistNow → foldRateSessions → foldRateSample`
   unboundedly after any 15-minute training session, crashing the client thread
   and losing the flush that exists to prevent data loss. (`80b7e37`)
2. **Mid-session enable silently lost edits** — enabling the plugin while logged
   in never activated a profile: `profile` stayed −1, every `persist()` no-oped,
   and the next login replay restored disk state over the user's goals/ticks.
   The first-tick seed now activates the profile exactly like LOGGED_IN.
   (`80b7e37`)
3. **captureSetup overcounted unstackables** — the per-id inventory total was
   written into every slot holding that id (3 sharks captured as 3+3+3), so
   `setupItemsToWithdraw` flagged phantom shortfalls in the farming/dailies
   withdraw lists. Same bug duplicated in LoadoutLab's capture. (`80b7e37`)
4. **Goals archive unreachable by click** — `GoalsHubTab.statSlab` self-listened
   without `MouseRelay`, so the only entry to the completed-goals archive died
   over the slab's label/count/icon (the codified 2026-07-27 trap); the
   currentTask card and task blocks likewise lost their right-click menus.
   Plus the same trap in PohTab tier rows, HunterRumoursTab location rows and
   PortTasksTab port rows. (`2902dd8`)
5. **1.77 MB pack parsed per row per render on the EDT** —
   `LoadoutLabModule.itemSourcesPack()` built a fresh `DataPack` per call
   (the memo is per-instance), Gson-parsing item-sources.json once per unowned
   wiki-gear row per accepted render pass. Measured: **35 ms per parse → 0 µs**
   field-cached; pinned by `assertSame`. (`5a386f9`)
6. **Combat replan/rebuild storm per cast** — WMS slots-mode storages (rune
   pouch, bolt pouch, quiver) committed + broadcast on every amount-varbit
   change: one persist-and-notify per cast/shot, each driving the planner's
   replan and every visible tab's rebuild. Quantity churn now coalesces onto a
   ten-tick flush (AccountState's own cadence for the same varbits); item-set
   changes still flush next tick. Pinned: ten shots across ten ticks = 2
   commits, quantities honest. (`1795989`)
7. **Daily reset notification never fired for idle players** — the member
   `DailiesModule.outstanding()` delegated to the cross-module static that
   hardcodes `crossedReset=false`, so past 00:00 UTC every stale-claimed daily
   counted DONE: no notification (and the day stamped as told), infobox hidden,
   "Nothing to run" above rows the tab itself colours AVAILABLE. No detection
   premise changed — the member now counts exactly as the rows render.
   (`f81d947`)

## Fixed — mediums/lows by cluster

- **State core** (`80b7e37`): clogCatalog was a synchronizedList cleared+refilled
  on the client thread while EDT rebuilds iterated it unlocked (CME = half-built
  tab) — now a volatile immutable publish; boat/storage snapshots were mutated
  in place while EDT readers `copy()` them — now copy-on-write (pinned by a
  concurrency hammer); `supplyCheckpoint` leaked the old account's consumption
  baseline across profile switches; `migrateLegacyGoalSeeds` persisted
  mid-restore (torn profile on the synchronous path); plugin `shutDown` let one
  throwing module skip its siblings and the flush; `onConfigChanged` now
  marshals module start/stop to the EDT; `rateSessions` synchronized (EDT
  shutdown flush vs client-thread ticks).
- **UI core** (`84a6446`): RebuildGate lost a state change racing a tab-show
  (stale until the next change — now double-checked, pinned via a headless
  seam); MouseRelay never relayed exits so V2Table/V2Checklist hover bands stuck
  lit; SpriteCache cached lazily-produced `getScaledInstance` images that
  null-observer draws never complete (blank icons) — now real BufferedImages;
  V2Table's layout was O(rows²·cells) (~10,200 `getPreferredSize` calls for a
  50×4 table, pinned to ≤208); V2Label's ink cache grew unboundedly off live
  progress strings; `Format.hours` rendered 59.5–60 min as "60m".
- **Atom hygiene** (`2902dd8`): V2SpriteButton/V2ChipRow now fire on left press
  only, so relayed right-click menus can't double-fire the control under the
  pointer.
- **Module threading** (`792383f`): Poh sweep-state races (EDT Reset vs client
  sweep) + diagnostics rebuilds now gated; Hunter/Slayer lazy record loads
  synchronized; Hunter's shutdown map-point clear marshalled; Slayer re-enable
  re-highlights spawned task NPCs and drops a duplicate ungated rebuild; CA
  fingerprint now hashes the watched Combat-Profile kill varps (stale profile
  view); ClueStash re-sweeps STASH varbits after re-enable (pinned) and
  publishes its lazy index safely; BankSpace/FarmingTracker lazy indexes
  volatile; DailiesNew run events ride the RebuildGate.
- **WMS** (`1795989`): varbit watchers indexed (was a ~90-storage walk per
  VarbitChanged); syncStash baseline-swap-before-commit (was O(N²) re-entrant
  commits); module + scraper detection baselines re-derive off
  profileGeneration; partial name overrides no longer suppress resolution;
  storage commits tagged `Topic.STORAGE` and the tab scoped to it.
- **Engine** (`3128eb2`): bonus xp honours its startXp/endXp band and the
  banked share (Fishing 1→58 no longer credits ~19.7k phantom Agility/Strength
  xp — pinned three ways); OBTAIN projections credit `obtainQty`, not 1.
- **Render waste** (`f1cb221`): clog/gear-library sprite arrivals were routed
  into fingerprint-gated listeners and swallowed (blank icons); GearTab stacked
  ~180 onLoaded listeners per rebuild; BankTab's stats sprite one per rebuild
  (`addTo` now); Runway category icons never landed post-login; GearLibrary ran
  the ~3,900-item query+sort four times per rebuild per keystroke (now once,
  pinned by a query counter); clog fingerprint ignored count-only harvests;
  GoalsHub badge icons re-SCALE_SMOOTHed per row, archive rendered all 200
  records (now the ~50-row law), update banner could start permanently dead;
  Quests/Diaries hero emblems re-scaled twice per rebuild.
- **Final batch** (`c08739e`): farming transition state re-derives per profile
  (hop replayed "ready" notifications; a mid-run hop advanced A's run from B's
  patches) and `patchesAt` no longer walks the whole farming world per stop;
  PortTasks Held-Karp ranking memoized in the module for both surfaces (was
  ~590k DP iterations per state change with boards up); CluesTab evaluates each
  clue's requirement graph once per pass (was 3–4×); ExternalSync clears level
  baselines on startUp (bogus milestone webhook bursts) and percent-encodes the
  WOM path segment; BankedXp uses EnumMaps (deterministic tied-XP ordering);
  BankSpace ignored-items and Runway watchlist capped at ~50 with honest tails;
  the webhook config copy now promises only the implemented level milestones.

## Confirmed, NOT fixed — needs live verification or a ruling

Ranked; each with the blocker.

1. **`GoalsHubTab.java:1721` (medium)** — accepting a two-goal merge suggestion
   calls `setGoalPinned` per goal, but the single-pin invariant clears the
   first pin: only the LAST goal pins, the offer dismisses forever. Fix needs a
   ruling: a bulk-pin API for merge-accept vs. honest copy under the one-pin
   rule (the G7 "exactly one pin" ruling is Luke's).
2. **`GoalPlannerModule.java:418` (medium)** — the archive's "took Xh" records
   `plan.knownHours` from a plan that already EXCLUDES the completed goal — it
   shows the remaining hours of the OTHER goals. Fix needs a semantics
   decision: attribute the goal's own step-hours, or relabel the raw snapshot.
3. **`GoalExpander.java:184` (medium)** — `varbit:` currency requirements
   (e.g. Tithe points varbit 4893 for Gricoller's can) read from
   `state.getVarbit`, but nobody `watchVarbits` them — they read 0 forever and
   "Earn N points" never clears. Proposed: planner collects varbit ids from
   selected goals' requirement strings and watches them; touches detection
   wiring, wants a live pass.
4. **`WheresMyStuffScrapers.java:787` (medium)** — compost bins decode only on
   region CHANGE; filling a bin in place is invisible until leaving and
   returning. Fix (re-decode on varbit movement inside the region) changes the
   ported reference's detection premise — verify against the live transmit
   varbit first.
5. **`CollectionLogModule.java:446` (low)** — a Log Sync interrupted mid-stream
   (interface closed, hop) consumes a PARTIAL harvest and still pins the
   baseline to the full COLLECTION_COUNT, silently claiming a complete sync.
   Needs a completeness heuristic verified against live script 2240 behaviour.
6. **`CollectionLogModule.java:134` (low)** — `shutDown` leaves the injected
   Log Sync widget alive and clickable on the game interface; clicking it on a
   dead module shows "Syncing…" forever. Fix is client-thread widget teardown —
   live-verify the child-hiding against the log interface.
7. **`WheresMyStuffScrapers.java:1947` (low)** — raw `Integer.parseInt` on
   widget text (Mixology/GF shop) can throw out of `onGameTick`; the scrapers
   after it in dispatch order silently stop for the session. Fix is
   `NumberUtils.toInt` like the file's other sites — confirm live widget text
   formats during the module's planned in-client pass.
8. **`WheresMyStuffScrapers.java:236` (low)** — `bankWatcher` diffs an ~800-slot
   bank map every GameTick forever (the BANK container stays non-null after
   closing), feeding only the herb-sack empty-to-bank path. Gate it on
   bank-changed ticks — but verify herb-sack detection live; the port is
   byte-faithful to the reference.
9. **`PohTab.java:117` (low)** — PohTab (and siblings QolTab/RunwayTab/
   DailiesNewTab from the same rebuild arc) rebuild without a fingerprint
   compare, so a visible tab does full model rebuilds per broadcast. The CA/clog
   fingerprint pattern fits; deferred as a design-conformance pass across four
   rebuilt tabs rather than a spot patch.
10. **`GoalExpander.java:347` (low)** — `addObtain`'s merge path bumps
    `obtainQty` without re-running the KB purchase-cost reqs (a qty-5 stock
    merged over a qty-1 obtain keeps qty-1 purchase deps). A naive re-expansion
    would double-count qty-scaled purchase nodes (their ids differ per qty) —
    needs a considered re-expansion that replaces the old dep nodes.
11. **`StrategyClient.java:27` (low, dead code)** — the 2026-07-21 removal of
    the Activity/Wiki-tips strip orphaned `StrategyClient` + `WikiStrategy`
    (+ their OkHttp fetch and test). Zero references; deletion is Luke's call
    per the surgical-changes rule.
12. **`IronHubConfig` webhook senders (noted)** — clog slots/uniques/pets/goal
    completion webhooks remain unimplemented; the copy now says so. Wiring goal
    completions to the existing archive detector is a candidate follow-up.
